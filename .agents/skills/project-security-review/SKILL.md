# 틈새 보안 리뷰

기본 동작은 읽기 전용 보안 리뷰다. 취약점을 찾아도 코드를 수정하거나 설정을 바꾸지 않는다. 사용자가 수정까지 명시적으로 요청한 뒤에만 요청 범위의 변경을 수행한다.

## 리뷰 절차

1. `references/teumsae-security-context.md`를 읽고 현재 코드·lockfile·배포 설정과 대조한다. 문서의 버전 정보는 시작점이며 현재 상태를 다시 확인한다.
2. `~/.codex/skills/security-best-practices/SKILL.md`가 있으면 읽고, 프로젝트의 JavaScript/TypeScript 공통 및 Next.js 서버·React 프런트엔드에 해당하는 모든 참조를 적용한다. 공통 스킬을 찾을 수 없으면 설치되어 있지 않다고 사용자에게 알리고 프로젝트 기준으로 리뷰한다. 사용자가 요청하지 않았다면 설치하지 않는다.
3. 입력부터 인증·권한 확인, 데이터 접근, 응답·화면 출력까지 실제 호출 경로를 추적한다. 중요한 보호가 코드 밖의 호스팅·Supabase 설정에 있을 수 있으면 실제 취약점으로 단정하지 말고 런타임 확인 항목으로 둔다.
4. 결과를 아래 두 범주로 분리한다.
   - **확인된 취약점:** 악용 경로가 코드·설정 근거로 성립하는 항목만 적는다. 심각도, 파일·줄, 근거, 전제 조건, 영향, 권장 대응을 포함한다.
   - **추가 검증 필요:** 저장소만으로 결론 낼 수 없는 항목, 필요한 브라우저·배포·DB 확인 방법을 적는다.
5. 한국어 Markdown으로 간결하게 보고한다. 코드에 보호가 안 보인다는 이유만으로 악용이 확인됐다고 단정하지 않는다. 수행하지 않은 런타임·DB·침투 검증을 통과했다고 표현하지 않는다. 파일 보고서는 사용자가 요청했거나 저장 위치를 지정한 경우에만 만든다.

## 작업 경계

- `.env*`, 쿠키, 브라우저 저장소, 로그에서 비밀값을 읽거나 출력하지 않는다. 환경값은 설정 여부만 확인한다.
- 외부 계정이나 실제 DB를 대상으로 하는 검증은 사용자가 명시적으로 요청하고 전용 테스트 환경이 있을 때만 수행한다.
- 보안 수정, 의존성 설치·업데이트, 원격 설정 변경은 리뷰 요청만으로는 하지 않는다.
