# 틈새 프론트엔드

사용자가 화면에서 보는 데이터의 출처를 분명히 한다. 수정 전 승인된 이슈나 디자인과 `docs/spec.md`의 관련 부분(§4~6)을 읽는다. 명세에서 제안으로 표시된 정책을 확정 사항으로 취급하지 않는다.

## 기본 명령

저장소 루트에서 `nvm use`로 `.nvmrc` 버전의 Node를 선택하고 pnpm을 사용한다. 의존성이 없거나 lockfile이 바뀐 경우에만 `pnpm install --frozen-lockfile`을 실행한다.

| 목적 | 명령 |
| --- | --- |
| 로컬 화면 실행 | `pnpm dev` |
| 자동 테스트 | `pnpm test` |
| 타입 검사 | `pnpm typecheck` |
| 린트 | `pnpm lint` |
| 프로덕션 빌드 | `pnpm build` |

화면 변경 후에는 해당 흐름을 데스크톱과 모바일 화면에서 직접 확인한다. 전체 변경 검증이 필요하면 `teumsae-qa` 스킬의 CI 순서도 실행한다.

## 형제 워크트리에서 로컬 환경 연결

새 기능 워크트리에서 로컬 화면이나 인증(카카오 로그인 포함)을 확인할 때는 개발 서버를 실행하기 전에 원본 프로젝트의 `.env.local` 연결을 확인한다.

- 원본 프로젝트와 현재 워크트리의 Git 상태를 확인하고 기존 파일을 보존한다. `.env.local`은 존재 여부와 파일 종류·링크 대상만 확인하며 내용을 열거나 출력하지 않는다.
- 원본 프로젝트에 `.env.local`이 있고 워크트리에는 파일이 없으면, 값을 복사하지 말고 원본 파일을 가리키는 상대 경로 심볼릭 링크를 워크트리에 만든다. 이 사용자 설정은 이미 승인되어 있으므로 다시 묻지 않는다.
- 워크트리에 `.env.local` 파일이나 링크가 이미 있으면 덮어쓰지 않는다. 링크라면 대상 경로만 확인하고, 일반 파일이거나 대상이 다른 링크이면 그대로 보존한다.
- 연결 뒤 `test -L .env.local`, `test -e .env.local`, `readlink .env.local`, `git check-ignore -q .env.local`로 링크·대상·무시 규칙을 확인한다. 환경변수 값은 터미널·로그·PR에 출력하지 않는다.
- 이 저장소처럼 `teumsae-worktrees/<기능>`이 `teumsae`와 같은 상위 폴더 아래 있으면 링크 예시는 `ln -s ../../teumsae/.env.local .env.local`이다. 실제 경로가 다르면 원본 프로젝트를 가리키는 상대 경로를 계산한다.
- 원본 설정 파일이 없으면 새 비밀값을 만들거나 다른 환경의 키를 복사하지 말고, 사용자에게 로컬 설정이 필요하다고 알린다. 로그인 리다이렉트 URI의 실제 호스트 설정은 UI 환경 파일 연결과 별도로 확인한다.

## 클라이언트 상태와 서버 데이터

- 서버에서 온 데이터와 비동기 요청 상태는 TanStack Query가 소유한다. query key에는 로그인 사용자 ID와 조회 조건을 포함해 사용자·기간 간 캐시가 섞이지 않게 한다.
- QueryClient 기본값은 `staleTime: 60_000`, `gcTime: 600_000`, `refetchOnWindowFocus: false`, `retry: 1`이다. 폴링은 제품 요구와 DB 부하 근거가 있을 때만 추가한다.
- 생성·수정·삭제 성공 후 영향받는 사용자 query key를 무효화하거나 결과로 캐시를 갱신한다. 로그아웃·계정 전환 시 사용자 데이터 캐시를 비운다.
- Zustand는 여러 클라이언트 컴포넌트가 공유하는 임시 UI 상태만 보관한다. 일정 데이터나 서버 응답을 Zustand에 복사하지 않는다.
- 링크로 공유하거나 새로고침 후 유지해야 하는 날짜·보기 등 탐색 상태는 URL을 기준으로 삼고 Zustand에 중복 저장하지 않는다.
- Next.js App Router에서 Zustand store는 요청 간 공유되는 모듈 싱글턴으로 만들지 말고 provider 범위에서 생성한다.

## 화면 흐름

- 일정 확인 → 빈 시간 검색 → 날짜가 표시된 후보 선택 → 등록 확인 → 저장 결과의 연결을 살핀다. 후보를 고르는 것만으로 일정이 생성되지는 않는다.
- 후보와 확인 카드에 날짜·요일·시간을 모두 표시한다. 패널을 열고 닫거나 화면 크기가 바뀌어도 선택한 후보를 알아볼 수 있게 한다.
- 샘플 데이터와 화면에서만 반영되는 동작을 명시한다. 서버가 저장 성공을 반환한 뒤에만 DB 저장 완료를 알리고 달력과 선택일 목록을 갱신한다.
- 로딩, 빈 일정, 빈 시간 없음, 조회 실패, 저장 실패를 구분한다. 저장에 실패하면 입력과 확인 카드를 유지한다.
- 변경한 조작 요소의 키보드 접근, 레이블, 포커스, 비활성화·처리 중 상태를 데스크톱과 모바일에서 확인한다. 모바일에서도 일정 확인과 후보 선택·등록 확인을 완료할 수 있어야 한다.

예: 두 번째 후보를 고르면 실제 날짜와 시간이 적힌 확인 카드가 열린다. 확인을 누른 뒤에는 처리 중 상태를 보이고, 서버의 저장 성공 응답을 받은 경우에만 달력과 목록을 갱신한다. 샘플 화면이라면 로컬 상태만 바꾸고 그 사실을 표시한다.

영향받는 흐름을 데스크톱과 모바일 크기에서 확인한다. 실제 화면에서 관찰한 결과와 코드 검사 결과를 구분해 기록한다.
