# 빈 시간 후보 더 보기 구현 계획

> **작업 방식:** 현재 세션에서 순서대로 구현한다. 각 단계는 테스트 우선으로 진행한다.

**목표:** 최대 12개의 유효한 후보를 한 번 검색해 저장하고, AI 호출 없이 화면에서 3개씩 펼친다.

**구성:** 검색 서비스와 저장 RPC의 한도를 12로 맞춘다. UI는 첫 3개만 노출하고 로컬 상태로 다음 후보를 펼친다. 기존 후보 검증과 등록 확인 흐름은 재사용한다.

**기준 문서:** `docs/superpowers/specs/2026-10-30-availability-candidates-design.md`, `docs/spec.md` §5.1, §5.3, §6 F08.

## 전역 제약

- 새 라이브러리를 추가하지 않는다.
- 도구 입력과 DB의 후보 저장 상한을 함께 12로 둔다.
- 도구 검색 1회당 후보 최대 12개, UI 노출은 3개씩이다.
- 더 보기 클릭은 추가 요청이나 AI 호출을 만들지 않는다.
- 기존 시간순, 소유권, 만료, 설정 버전, 일정 충돌 검증을 유지한다.

## 검토할 실패 조건

- 후보가 0개 또는 3개 이하일 때 더 보기 버튼을 보이지 않는다.
- 후보가 4~12개면 남은 개수만큼 펼친다.
- 12개를 넘는 후보가 있으면 12개 이후에 추가 검색 조건 안내를 보인다.
- 후보 선택은 원래 서버 후보 ID와 연결되며 선택 순번이 달라지지 않는다.
- 후보가 저장 만료되거나 설정 버전이 바뀌면 기존 서버 검증이 계속 거부한다.
