# 일정 서버 캐시와 전역 UI 상태 설계

## 목적
일정 범위 조회의 반복 요청을 줄이고, 서버 데이터와 클라이언트 UI 상태의 소유 위치를 분명히 한다.

## 결정
- 일정 데이터 조회는 TanStack Query가 소유한다. 키는 사용자 ID와 조회 시작·종료 시각을 포함한다.
- 브라우저의 인증 Supabase 클라이언트로 읽고, DB의 기존 RLS가 본인 일정만 반환하도록 한다. 쓰기는 기존 Server Actions와 DB 함수를 유지한다.
- Query 기본값은 `staleTime: 60_000`, `gcTime: 600_000`, `refetchOnWindowFocus: false`, `retry: 1`이다. 주기적 폴링은 쓰지 않는다.
- 생성·수정·삭제 성공 후 해당 사용자 일정 키를 무효화해 현재 범위를 다시 읽는다. 서버 렌더의 일정 조회와 `router.refresh()`는 제거한다.
- Zustand는 일정 폼 열기·편집 대상처럼 화면에서 공유하는 임시 UI 상태만 소유한다. 일정 데이터는 보관하지 않는다.
- 날짜와 달력 보기 모드는 공유 가능한 URL 상태로 유지한다. 로그아웃하면 Query 캐시와 일정 UI 상태를 초기화한다.

## 범위 밖
- 영구 캐시, localStorage, 실시간 구독, 자동 폴링, 낙관적 DB 변경은 추가하지 않는다.
- 캐시 만료는 DB 요청을 줄이는 대신 다른 세션의 변경 반영을 최대 1분 늦출 수 있다.

## 완료 조건
- 같은 사용자·기간 쿼리는 1분 내 재방문 시 캐시를 사용하고, 서버 변경 성공 후에는 즉시 무효화된다.
- 서로 다른 사용자와 날짜 범위가 캐시 키에서 분리된다. 로그아웃 후 이전 일정 데이터가 남지 않는다.
- 로딩·조회 실패·빈 일정 상태를 구분하고 실제 브라우저와 DB 검증 여부를 별도로 보고한다.
