# 빈 시간 후보 더 보기 설계

## 의도

소요 시간이 지정된 빈 시간 검색에서 후보를 세 개만 볼 수 있던 불편을 줄인다. 첫 화면에는 세 개만 보여주고, 더 보기는 추가 AI 호출 없이 이미 검색·검증·저장된 후보를 차례로 펼친다.

## 접근 방식

- 기존 최대 3개 제한을 유지하면 더 많은 후보를 고를 수 없다.
- 검색을 다시 요청할 때마다 다음 후보를 계산하면 서버와 DB 요청이 늘어난다.
- 선택한 방식: 한 번의 검색에서 최대 12개 후보를 계산해 저장하고, 화면은 3개씩 펼친다. 12개를 넘어 후보가 더 있으면 날짜나 조건을 좁히도록 안내한다.

## 범위와 제약

- 선택 후보의 날짜·시간, 만료, 설정 버전 및 소유자 검증은 기존 서버·DB 검증을 유지한다.
- 후보 ID와 후보 순서는 기존 대화 상태와 카드 구조를 따른다.
- 화면의 더 보기 동작은 모델/API/DB를 추가 호출하지 않는다.
- 저장 가능한 후보 총량은 12개로 제한해 장기간 검색 결과가 대화·DB에 무제한 쌓이지 않게 한다.

## 완료 조건

- 서버가 최대 12개까지 시간순 후보를 반환하고 더 있는지 표시한다.
- 카드 첫 화면에는 3개를 보이고 버튼을 누를 때마다 최대 3개씩 추가로 보인다.
- 모든 표시 후보는 기존 등록 확인 흐름으로 선택할 수 있다.
- 관련 테스트, 타입 검사, 린트가 통과한다. SQL 마이그레이션은 로컬 DB가 구성되지 않았으면 실제 적용했다고 보고하지 않는다.
