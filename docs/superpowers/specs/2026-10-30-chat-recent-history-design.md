# 최근 AI 대화 복원 설계

## 의도와 목표
새로고침 뒤에도 사용자가 직전에 나눈 일정 대화를 다시 보고 이어갈 수 있게 한다. 개인 일정이 담길 수 있으므로 대화 본문을 브라우저 저장소에 복제하지 않고 기존 사용자별 DB 기록을 사용한다.

## 범위
- 로그인한 사용자의 가장 최근 대화 하나를 복원한다.
- 기존 24시간 만료와 소유자별 RLS를 유지한다.
- 장기 보관, 대화 목록·검색, 기기 간 대화 아카이브 UI는 후속으로 둔다.
- 패널 열림 여부와 작성 중인 입력은 기존 컴포넌트 상태로 둔다.

## 접근 방식
- 브라우저 메모리만 유지하면 새로고침에서 대화가 사라진다.
- localStorage에 전체 transcript를 두면 개인 일정 문장이 기기에 남고 DB와 이중 저장된다.
- 기존 대화 DB에 화면 transcript를 추가하고 인증된 API로 최근 대화를 복원하는 방식을 선택한다. 서버 문맥은 AI 후속 질문에, transcript는 화면 복원에 각각 사용하며, TanStack Query로 사용자별 서버 응답을 캐시한다.

## 동작과 제한
성공한 사용자·AI 메시지와 결과 카드를 기존 대화 행에 저장한다. 최근 대화 조회는 인증된 사용자 ID로만 수행하며 24시간이 지난 대화는 반환하지 않는다. 만료 행은 다음 AI 요청에서 정리된다. 등록 확인 카드 상태는 확인·취소 API 결과에 맞춰 갱신한다. 대화 기록은 AI 모델에 추가 요청하지 않고 복원한다.

## 구현 판단
화면 transcript는 별도 JSONB 컬럼에 저장해 모델 입력 문맥 형식과 분리한다. 저장·조회 API 응답은 private no-store로 제한한다. 사용자별 query key를 쓰고 로그아웃 시 기존 QueryClient 정리 규칙을 따른다.
