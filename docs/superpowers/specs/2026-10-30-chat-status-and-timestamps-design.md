# AI 대화 상태와 시간 표시 설계

## 목표
사용자가 대화만 보고 실제 일정 저장 여부를 구분하고, 미등록된 제안을 다시 확인할 수 있게 한다. 각 메시지의 시각과 날짜 구분선을 표시한다.

## 사용자 흐름
- 저장된 제안은 `일정에 추가됨` 상태와 대화 시각으로 표시하고 다시 확인 버튼을 감춘다.
- 유효한 미확인 제안은 `등록 전 · 확인 필요`와 확인 버튼을 표시한다.
- 만료·취소·충돌·설정 변경 제안은 `등록되지 않음` 상태와 이유를 표시한다.
- 사용자가 `이 내용으로 다시 제안`을 누르면 서버가 사용자 소유 transcript의 원래 내용을 찾아 현재 가능 시간과 지난 시각을 검증한다. 유효할 때 새 확인 카드를 만들며, 저장은 새 확인 버튼을 누른 뒤에만 진행한다.
- 대화 재생성은 AI 모델을 호출하지 않는다. 요청 ID를 사용해 네트워크 재시도에도 중복 제안을 만들지 않는다.
- 메시지마다 한국 시간 기준 시각을 표시하고, 날짜가 바뀔 때만 요일·날짜 구분선을 추가한다.

## 상태의 근거
사용자 인증을 확인하는 제한된 RPC에서 제안의 실제 상태를 복원한다. transcript의 `pending`은 유효기간이 지났으면 `expired`로 갱신한다. 저장 완료 표시에는 서버의 `confirmed` 상태가 필요하다. 재제안은 DB에 저장된 카드 내용만 사용하고, 인증된 사용자와 활성 conversation에 묶는다.

## 경계
- 일정은 재제안 동작만으로 저장하지 않는다.
- 현재 가능 시간 밖, 일정 불가 날짜, 지난 시각, 겹치는 일정이면 새 확인 카드를 만들지 않고 이유를 안내한다.
- AI 대화의 24시간 복원, transcript 50개 제한을 유지한다.
- 장기 대화 아카이브와 사용자 삭제 정책은 후속 범위다.

## 확인 기준
- 새로고침 뒤에도 메시지 시각·날짜 구분선·등록 상태가 복원된다.
- 확인 성공만 `일정에 추가됨`으로 표시한다.
- 만료된 미등록 제안은 다시 제안 가능하고 새 확인을 요구한다.
- 중복 요청으로 동일 재제안이 여러 개 생기지 않는다.
- 데스크톱과 모바일에서 상태·버튼·시간이 확인 가능하다.
