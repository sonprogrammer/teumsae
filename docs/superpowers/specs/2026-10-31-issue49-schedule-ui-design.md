# 이슈 49 일정 화면 UI/UX 설계

## 의도

일정 조회 중에는 갱신 상태를 분명하게 보여주고, 수동 등록·수정·삭제를 더 쉽게 찾고 조작할 수 있게 한다.

## 목표

- 최초 일정 조회에는 현재 스켈레톤 상태를 사용한다. 기존 데이터가 있는 상태에서 다시 불러올 때는 일정을 유지하고 작은 진행 표시를 보여준다.
- 일정 카드 제목뿐 아니라 카드 전체에 hover·focus 강조를 준다.
- 선택일 일정 패널 안에서 등록 폼을 펼친다. 폼이 열리면 중복되는 상단 추가 버튼을 숨기고, 폼 안의 닫기·취소 동작을 사용한다.
- 일정 수정·삭제는 Lucide 아이콘 버튼으로 표시하고 접근성 이름을 제공한다.
- 데스크톱과 모바일에서 일정 조회와 직접 등록 흐름을 사용할 수 있고, 동작에는 전환 효과를 주되 모션 감소 설정을 따른다.

## 비목표

- 일정 CRUD 서버 동작, DB 스키마, 인증, 저장 규칙은 바꾸지 않는다.
- 별도 편집 페이지나 새로운 UI 라이브러리를 도입하지 않는다.
- 재조회 중 기존 일정을 지우거나 전체 화면을 로딩 화면으로 바꾸지 않는다.

## 접근 선택

1. **선택일 패널 안에서 폼 확장 (선택)**: 이미 일정 등록 폼이 선택일 패널에 표시되므로 이 흐름을 유지한다. 상단 추가 버튼은 폼이 열리는 동안 감추고, 일정 카드 전체에 상태 강조와 아이콘 동작을 둔다. 기존 문맥을 유지하고 변경 범위가 작다.
2. **등록·수정 모달 또는 바텀시트 통합**: 카드 목록과 폼을 분리해 집중하기 쉽지만, 현재 수동 등록과 수정의 표시 방식이 달라져 편집 흐름을 함께 재구성해야 한다.

## 동작 세부

- 초기 로딩은 기존 플레이스홀더 스켈레톤을 사용한다.
- 기존 데이터가 있고 쿼리가 다시 실행될 때만 달력/일정 영역에 얇은 진행 표시와 보조기기용 상태 문구를 보인다. 데이터와 레이아웃은 유지한다.
- 카드 전체의 hover·focus-within 스타일을 강화하되 제목 상세 보기와 수정·삭제 버튼의 개별 동작을 유지한다.
- 수정·삭제 아이콘에는 `aria-label`과 툴팁을 제공한다. 삭제 확인 다이얼로그 흐름은 유지한다.
- 폼 전환 애니메이션은 짧게 적용하고 `prefers-reduced-motion` 환경에서는 줄인다.
- 기존 빈 상태, 조회 실패, 저장 실패 처리는 유지한다.

## 제약과 검증

- 현재 코드 기준은 Next.js App Router, TypeScript, Tailwind 및 기존 CSS, TanStack Query, Zustand다.
- 새로운 의존성을 추가하지 않고 기존 컴포넌트와 시각 규칙을 우선 사용한다.
- 자동 검사와 함께 데스크톱·모바일에서 최초 로딩, 재조회, 카드 포인터/키보드 강조, 폼 열기·닫기, 아이콘 동작을 확인한다.
