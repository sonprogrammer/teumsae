# 설정 화면 탐색 및 모바일 불가일 입력 설계

## 의도
설정 화면에서 일정 추천 설정과 알림 설정을 쉽게 찾아 쓰고, 모바일에서도 일정 불가일의 시작일·종료일을 무리 없이 입력할 수 있게 한다.

## 목표와 제외 범위
- 목표: 요일별 가능 시간, 일정 불가일, 알림을 각각 찾아 설정하고, 모바일 날짜 입력의 너비와 조작 순서를 개선한다.
- 목표: 알림 켜기·끄기를 현재 상태가 분명한 스위치 토글로 제공한다.
- 목표: 기존 저장 API, 입력 검증, 알림 구독 동작과 사용자 설정 데이터를 유지한다.
- 제외: 새 설정 기능, 인증·DB·푸시 서버 변경, 기존 설정 데이터 형식 변경.

## 접근 방식
1. 현재처럼 한 페이지에 카드만 나열하고 반응형 입력만 개선한다. 변경량은 적지만 긴 페이지와 설정 간 구분 문제를 해결하지 못한다.
2. 한 페이지에 카테고리 탐색과 상세 패널을 둔다. 데스크톱은 좌측 메뉴와 우측 상세, 모바일은 설정 목록에서 상세로 진입하고 명시적 뒤로 가기로 목록에 복귀한다. 현재 설정 수에 맞고 이후 확장도 가능하다.
3. 각 범주를 별도 URL 페이지로 분리한다. 딥링크는 분명해지지만 현 설정 수에 비해 라우트와 공통 UI가 늘어난다.

## 선택안
2번을 선택한다. 설정은 `요일별 가능 시간`, `일정 불가일`, `알림` 세 항목으로 나눈다. 목록 첫 화면에서는 항목을 미리 선택하지 않는다. 상세 헤더는 왼쪽에 목록 복귀 버튼, 오른쪽에 제목과 부제목을 둔다. 900px 이하의 태블릿 폭은 메뉴를 상세 위에 배치한다. 700px 이하 모바일은 설정 목록을 먼저 보여주고, 선택하면 상세와 목록 복귀 버튼을 보여준다.

알림 켜기·끄기는 레이블이 있는 스위치 토글로 표시한다. 스위치를 켜면 브라우저 권한 요청, 구독 등록, 기존 서버 설정 저장을 순서대로 수행한다. 처리 중에는 토글 조작을 막고 진행 상태를 표시한다. 권한 거부·설정 누락·저장 실패 때 성공 상태로 바꾸지 않고 기존 상태와 오류 안내를 보여준다. 끄기는 기존 비활성화·구독 해제 흐름을 사용한다.

요일별 가능 시간과 일정 불가일은 각각 별도의 저장 버튼을 갖는다. 기존 DB/API의 한 설정 객체를 유지하되 저장하는 범주 외의 값은 최신 조회값으로 보존한다. 일정 불가일 폼은 모바일에서 시작일과 종료일 입력을 각각 전체 너비로 세로 배치한다. 이름과 추가 동작은 입력 흐름에 이어 배치하고, 입력 폭이 줄거나 가로 넘침이 생기지 않게 한다. 데스크톱은 현재처럼 가로 배치를 유지할 수 있다.

## 상태와 동작
- 설정 조회 로딩·실패·재시도 상태를 선택한 범주의 상세 안에서 유지한다.
- 저장 성공·실패 안내와 입력값 보존을 기존 동작대로 유지한다.
- 범주 이동 시 편집 중인 설정값을 잃지 않도록 상세 패널의 마운트 상태를 유지한다. 목록 첫 화면과 목록 복귀 후에는 선택 상태를 비운다.
- 모바일에서 상세 진입·목록 복귀 시 제목과 키보드 초점을 적절히 이동한다.

## 구현 경계
`/schedule/settings`와 기존 설정 저장·조회 API를 유지한다. 설정 페이지 레이아웃, 설정 메뉴/상세 UI, 푸시 토글 UI, 일정 가능 시간 컴포넌트의 불가일 입력 레이아웃과 관련 스타일만 변경한다. 사용 중인 Next.js 버전의 관련 로컬 문서를 확인한 뒤 구현한다.

## 검증 기준
- 데스크톱에서 세 항목을 전환하고 각 설정을 사용할 수 있다. 첫 진입에는 어느 항목도 선택된 모양으로 표시하지 않는다.
- 모바일에서 설정 목록 → 각 상세 → 목록 복귀가 가능하고, 복귀 시 포커스가 목록 제목으로 이동한다.
- 요일별 가능 시간만 저장해도 불가일이 유지되고, 불가일만 저장해도 요일별 가능 시간이 유지된다.
- 상세 헤더에서 왼쪽 목록 복귀 버튼과 오른쪽 제목·부제목이 함께 보이며 영문 `SCHEDULE PREFERENCES`가 없다.
- 320~390px 모바일과 701~900px 중간 폭에서 입력이 잘리거나 가로 스크롤을 만들지 않는다.
- 알림 토글은 처리 중 중복 조작을 막고, 권한·설정·저장 실패 시 잘못된 켜짐 상태를 보이지 않는다.
- 조회 실패 시 재시도할 수 있고 저장 실패 시 작성한 변경이 남는다.
- 관련 타입 검사, 린트, 테스트 및 프로덕션 빌드가 통과한다.
